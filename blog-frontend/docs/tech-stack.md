# 博客重构项目技术栈说明

## 1. 项目定位

本项目旨在重构个人博客系统，将原本手写架构升级为现代化、可维护、易发布的博客平台。

核心目标：

- 前台页面更加美观、现代、响应式；
- 后台可以快速发布和管理文章；
- 文章、分类、标签、封面图等内容统一由后台管理；
- 前后端解耦，方便后续扩展；
- 支持后续部署上线和持续维护。

---

## 2. 整体架构

项目采用“前台展示 + 后台内容管理 + 数据库存储”的架构。

```txt
用户访问博客
    ↓
Next.js 前台页面
    ↓
请求 Directus API
    ↓
Directus 管理内容
    ↓
数据库存储文章数据
````

其中：

* **Next.js** 负责博客前台展示；
* **Tailwind CSS** 负责页面样式；
* **Directus** 负责后台内容管理；
* **数据库** 负责存储文章、分类、标签、图片等数据；
* **API** 负责连接前台和后台。

---

## 3. 前端技术栈

| 技术           | 作用                      |
| ------------ | ----------------------- |
| Next.js      | React 应用框架，用于构建博客前台     |
| React        | 构建页面组件，例如文章卡片、导航栏、页脚    |
| TypeScript   | 提供类型约束，提高代码可靠性          |
| Tailwind CSS | 快速编写现代化、响应式页面样式         |
| App Router   | Next.js 新版路由系统，用于组织页面结构 |

### 前端主要职责

* 首页展示；
* 文章列表展示；
* 文章详情页展示；
* 分类页、标签页展示；
* 关于页面展示；
* 从 Directus API 获取文章数据；
* 渲染 Markdown / 富文本内容；
* 做 SEO 优化；
* 适配移动端和桌面端。

---

## 4. 后端 / CMS 技术栈

| 技术                     | 作用                     |
| ---------------------- | ---------------------- |
| Directus               | 无头 CMS，用于管理文章、分类、标签、图片 |
| REST API / GraphQL API | 提供内容数据接口               |
| Role & Permission      | 控制后台权限和公开访问权限          |
| File Library           | 管理文章封面图、插图等资源          |

### Directus 主要职责

* 提供可视化后台；
* 创建文章、分类、标签等数据表；
* 管理文章内容；
* 上传和管理图片；
* 自动生成 API；
* 控制公开文章的访问权限。

---

## 5. 数据库技术栈

| 技术                          | 作用       |
| --------------------------- | -------- |
| PostgreSQL / MySQL / SQLite | 存储博客内容数据 |

第一版可以根据部署方式选择数据库：

* 本地学习和测试：SQLite；
* 正式部署和长期使用：PostgreSQL；
* 如果已有 MySQL 环境，也可以使用 MySQL。

### 核心数据表设计

第一版主要包含：

```txt
posts       文章表
categories  分类表
tags        标签表
files       图片资源，由 Directus 管理
```

文章表核心字段：

| 字段           | 说明                        |
| ------------ | ------------------------- |
| title        | 文章标题                      |
| slug         | 文章 URL 标识                 |
| summary      | 文章摘要                      |
| content      | 文章正文                      |
| cover        | 文章封面图                     |
| status       | 文章状态，例如 draft / published |
| published_at | 发布时间                      |
| category     | 所属分类                      |
| tags         | 文章标签                      |

## 10. 技术选型理由

### 为什么使用 Next.js？

Next.js 基于 React，适合构建现代博客系统。它支持文件路由、服务端渲染、静态生成、SEO 优化和灵活部署，适合个人博客长期维护。

### 为什么使用 Tailwind CSS？

Tailwind CSS 可以快速完成页面布局和样式设计，适合快速重构博客界面，减少手写 CSS 的复杂度。

### 为什么使用 Directus？

Directus 可以直接把数据库变成可视化后台，并自动生成 API。这样可以避免从零开发后台管理系统，快速实现文章发布、编辑、分类、标签和图片管理。

### 为什么前后端解耦？

前后端解耦后，前台可以专注展示效果，后台可以专注内容管理。后续如果要更换前端样式、增加移动端、接入小程序或其他客户端，也更容易扩展。
