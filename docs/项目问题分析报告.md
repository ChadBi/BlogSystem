## 二、严重问题（必修）

### S1. `/dashboard` 与 `/editor` 公开访问且 Sidebar 暴露入口

- **文件**：[app/dashboard/page.tsx](file:///d:/Project/BlogSystem/blog-frontend/app/dashboard/page.tsx)、[app/editor/page.tsx](file:///d:/Project/BlogSystem/blog-frontend/app/editor/page.tsx)、[components/Sidebar.tsx](file:///d:/Project/BlogSystem/blog-frontend/components/Sidebar.tsx) 第 12-13 行
- **描述**：两个具有后台性质的页面没有任何鉴权，且 Sidebar 把它们作为公开菜单项展示给所有访客。当前仅静态展示，但一旦后续接入真实写操作，会立刻成为越权漏洞。
- **修复方向**：
  1. 用 Next.js Middleware（`export function middleware(request)`）校验 session/cookie，未登录重定向到 `/login`；
  2. 从公开 Sidebar 中移除这两个入口，或仅在登录态显示。

### S2. `slug` 未编码且 `getPostBySlug` 缺少 status 过滤

- **文件**：[lib/directus.ts:73](file:///d:/Project/BlogSystem/blog-frontend/lib/directus.ts#L73)
- **描述**：
  ```ts
  `/items/posts?filter[slug][_eq]=${slug}&fields=*,category.*,tags.tags_id.*`
  ```
  存在两处问题：
  1. `slug` 未 `encodeURIComponent`，攻击者可构造 `slug=foo&filter[status][_eq]=draft` 之类参数注入；
  2. 查询未加 `&filter[status][_eq]=published`，**任意状态（含草稿）的文章都能被取到**，存在越权读取草稿风险。
- **修复方向**：`encodeURIComponent(slug)` + 显式追加 `&filter[status][_eq]=published`。

### S3. `fetchDirectus` 把所有失败都吞成 `null`，线上不可观测

- **文件**：[lib/directus.ts:9-22](file:///d:/Project/BlogSystem/blog-frontend/lib/directus.ts#L9-L22)
- **描述**：
  ```ts
  if (!DIRECTUS_URL) return null;
  if (!res.ok) return null;
  catch { return null; }
  ```
  三处都返回 null，调用方无法区分「未配置 Directus」「网络失败」「HTTP 4xx/5xx」「响应体解析失败」。生产环境 Directus 401/500/网络故障都会被静默掩盖，页面静默 fallback 到 mock 数据而无人察觉。
- **修复方向**：
  1. 至少 `console.error` 记录状态码与路径（开发环境）；
  2. 推荐返回 discriminated union `{ ok: true; data } | { ok: false; reason }`；
  3. 生产环境可接入 Sentry / 自托管日志。

## 三、中等问题（应修）

### M1. `getPosts` 不支持分页，全量拉取

- **文件**：[lib/directus.ts:64-91](file:///d:/Project/BlogSystem/blog-frontend/lib/directus.ts#L64-L91)
- **描述**：5 个函数都硬编码查询参数，调用方无法自定义分页/排序/过滤。`getPosts` 不带 `limit`，会一次性拉取全部已发布文章。首页只需 4 篇（[app/page.tsx:23](file:///d:/Project/BlogSystem/blog-frontend/app/page.tsx#L23) 用 `slice(0,4)`），却拉全量。
- **修复方向**：为函数增加可选参数 `{ limit?, page?, sort?, filter? }`，首页调用 `getPosts({ limit: 4 })`。

### M2. `getPostBySlug` 缺 `limit=1` 且 slug 未编码

- **文件**：[lib/directus.ts:73](file:///d:/Project/BlogSystem/blog-frontend/lib/directus.ts#L73)
- **描述**：缺 `&limit=1`，Directus 会返回所有 slug 匹配项后再取 `[0]`；slug 未做 `encodeURIComponent`（与 S2 同源）。
- **修复方向**：加 `&limit=1` + `encodeURIComponent(slug)`。

### M3. `getFriends` 未做 normalize，avatar 的 file UUID 不会转换为 URL

- **文件**：[lib/directus.ts:88-91](file:///d:/Project/BlogSystem/blog-frontend/lib/directus.ts#L88-L91)
- **描述**：`getFriends` 直接返回 Directus 原始数据。但 `directus-schema.md:42` 定义 `avatar` 是 file 类型，若 Directus 中 avatar 存的是文件 UUID，前端会渲染 UUID 而非图片。`tags` 标为 `json`，也未解析。
- **修复方向**：增加 `normalizeFriend`，将 avatar 的 file UUID 转换为 `${DIRECTUS_URL}/assets/{id}`。

### M4. `Category.count` / `Tag.count` 未映射，UI 永远显示 0

- **文件**：[lib/directus.ts:24-62](file:///d:/Project/BlogSystem/blog-frontend/lib/directus.ts#L24-L62)
- **描述**：`normalizePost` 未映射 `Category.count` 与 `Tag.count` 字段（类型中有 `count?: number`，mock-data 也提供了）。Directus 不通过 aggregate 不会返回 count，导致 [app/categories/page.tsx:18](file:///d:/Project/BlogSystem/blog-frontend/app/categories/page.tsx#L18) 的「{cat.count ?? 0} 篇」永远显示 0。
- **修复方向**：在 `getCategories`/`getTags` 中用 `?fields=*,posts.id` 或 aggregate 接口统计文章数；或在前端用 `getPosts` 后聚合。

### M5. `NEXT_PUBLIC_DIRECTUS_URL` 公开前缀泄露内部 URL

- **文件**：[lib/directus.ts:4](file:///d:/Project/BlogSystem/blog-frontend/lib/directus.ts#L4)
- **描述**：`NEXT_PUBLIC_DIRECTUS_URL` 用了公开前缀，但 directus.ts 只在 Server Component 中被调用。公开前缀会导致 Directus 地址被嵌入客户端 bundle，**泄露内部 URL**。
- **修复方向**：改为 `DIRECTUS_URL`（去掉 `NEXT_PUBLIC_`），仅服务端可见；并在文件顶部加 `import 'server-only';`。

### M6. `images.remotePatterns` 过于宽松且配置无效

- **文件**：[next.config.mjs:4-16](file:///d:/Project/BlogSystem/blog-frontend/next.config.mjs#L4-L16)
- **描述**：
  1. `hostname: '**'` 通配符过于宽松，允许任意 HTTPS 主机作为图片源，潜在 SSRF 风险；
  2. 配置存在，但全项目**未使用 `next/image`**（所有图都用 `<img>`，如 [PostCard.tsx:21](file:///d:/Project/BlogSystem/blog-frontend/components/PostCard.tsx#L21)、[posts/[slug]/page.tsx:32](file:///d:/Project/BlogSystem/blog-frontend/app/posts/%5Bslug%5D/page.tsx#L32)），该配置完全无效；
  3. `localhost:8055` 硬编码，生产环境 Directus 域名变更时无法通过环境变量调整。
- **修复方向**：把 hostname 收紧为实际 Directus 域名（从环境变量读取）；要么改用 `next/image`（性能更好），要么删除配置。

### M7. 未启用 `output: 'standalone'`，与部署文档不符

- **文件**：[next.config.mjs](file:///d:/Project/BlogSystem/blog-frontend/next.config.mjs)

### M8. `params` / `searchParams` 未声明为 Promise（升级 Next 15 会破坏）

### M9. 使用 `<a href>` 而非 `<Link>`，丢失客户端导航

### L1. `formatDate` 入参未校验
