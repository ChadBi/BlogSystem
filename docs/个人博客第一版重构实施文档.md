# 1. 项目最终目标

## 1.1 目标定位

本项目不是单纯换一个博客模板，而是把旧博客重构为一个完整的个人技术主页。

新的博客应该具备：

1. 独立后台；
    
2. 文章快速发布；
    
3. 前台自由设计；
    
4. 支持项目展示；
    
5. 支持分类和标签；
    
6. 支持友链；
    
7. 支持个人介绍；
    
8. 后期可扩展评论、搜索、访问统计、AI 摘要等功能。

# 2. 为什么选 Directus + Next.js

## 2.1 当前痛点

旧博客的问题本质上不是页面丑，而是架构不适合继续维护。

常见问题：

```txt
1. 页面结构自己写，后期难维护
2. 样式系统不统一，越改越乱
3. 写文章流程复杂
4. 每次更新都要重新构建
5. 没有后台管理
6. 文章、项目、友链等内容和代码混在一起
7. 想扩展功能时没有清晰的数据结构
```

---

## 2.2 新架构解决什么问题

新架构：

```txt
Directus：后台管理系统
PostgreSQL：数据库
Next.js：前台页面
Tailwind CSS：前端样式
```

对应解决方案：

|问题|解决方式|
|---|---|
|没有后台|Directus 提供后台|
|写文章麻烦|后台直接写文章|
|需要手动构建|前台从 API 读取内容|
|前端不好看|Next.js + Tailwind 自定义设计|
|文章和代码混在一起|内容存数据库|
|后期扩展困难|数据表结构清晰|

---

## 2.3 为什么不继续用 Hexo

Hexo 的典型流程：

```txt
写 Markdown
↓
生成静态页面
↓
构建
↓
部署
```

这种方式适合纯静态博客，但不适合你现在的需求。

你现在更想要：

```txt
后台写文章
↓
点击发布
↓
前台自动显示
```

所以 Hexo 不再是最合理选择。

---

## 2.4 为什么不直接用 WordPress

WordPress 的确很方便，但它的问题是：

```txt
1. 主题味比较重
2. 插件容易越装越乱
3. 前端自由度不如自己写 Next.js
4. 后期想做个人作品集和技术主页时会有束缚
5. 技术成长价值不如 Headless CMS + 前端项目
```

如果只是想最快上线普通博客，WordPress 可以。

但如果想做一个：

```txt
有个人风格
有技术展示
有后台管理
前端可控
后期可扩展
```

的博客系统，Directus + Next.js 更适合。

---

## 2.5 为什么不一开始自己写后台

自己写后台意味着你要写：

```txt
1. 登录
2. 权限
3. 文章增删改查
4. 分类管理
5. 标签管理
6. 文件上传
7. 图片管理
8. API 鉴权
9. 数据库设计

```

这些都很费时间，而且第一版没有必要。

你只需要专注于：

```txt
1. 数据表设计

3. 内容展示体验
4. 文章阅读体验
```

## 3.5 第四阶段：Directus 基础

Directus 需要重点学：

```txt
1. Collection：集合，对应数据库表
2. Field：字段，对应表字段
3. Relation：关系，比如文章属于分类，文章拥有多个标签
4. Role：角色
5. Permission：权限
6. Files：文件上传
7. API：前台读取内容
8. Status：草稿 / 发布 / 归档
9. Flow：自动化流程
10. Webhook：发布后通知前端刷新
```

第一版重点学前 8 个。

Flow 和 Webhook 可以第二版再做。

## 5.2 创建 Directus 环境变量文件

创建：

```bash
touch .env
```

写入：

```env
DIRECTUS_PORT=8055

DB_CLIENT=pg
DB_HOST=postgres
DB_PORT=5432
DB_DATABASE=blog
DB_USER=blog_user
DB_PASSWORD=blog_password

DIRECTUS_KEY=replace_with_random_key
DIRECTUS_SECRET=replace_with_random_secret

ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=admin_password_123456
```

注意：

正式部署时必须修改：

```txt
DIRECTUS_KEY
DIRECTUS_SECRET
ADMIN_EMAIL
ADMIN_PASSWORD
DB_PASSWORD
```

可以生成随机密钥：

```bash
openssl rand -base64 32
```

---

## 5.3 创建 docker-compose.yml

在 `directus-cms` 目录下创建：

```bash
touch docker-compose.yml
```

写入：

```yaml
services:
  postgres:
    image: postgres:16
    container_name: blog_postgres
    restart: always
    environment:
      POSTGRES_DB: blog
      POSTGRES_USER: blog_user
      POSTGRES_PASSWORD: blog_password
    volumes:
      - ./postgres-data:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  directus:
    image: directus/directus:latest
    container_name: blog_directus
    restart: always
    ports:
      - "8055:8055"
    depends_on:
      - postgres
    environment:
      KEY: ${DIRECTUS_KEY}
      SECRET: ${DIRECTUS_SECRET}

      DB_CLIENT: ${DB_CLIENT}
      DB_HOST: ${DB_HOST}
      DB_PORT: ${DB_PORT}
      DB_DATABASE: ${DB_DATABASE}
      DB_USER: ${DB_USER}
      DB_PASSWORD: ${DB_PASSWORD}

      ADMIN_EMAIL: ${ADMIN_EMAIL}
      ADMIN_PASSWORD: ${ADMIN_PASSWORD}

      PUBLIC_URL: "http://localhost:8055"

      CORS_ENABLED: "true"
      CORS_ORIGIN: "http://localhost:3000"
    volumes:
      - ./uploads:/directus/uploads
      - ./extensions:/directus/extensions
```

## 7.2 status 字段建议

字段名：

```txt
status
```

可选值：

```txt

published
archived
```

含义：

```txt
draft：草稿
published：已发布
archived：归档
```

前台只显示：

```txt
status = published
```

## 7.3 slug 字段说明

slug 是文章 URL。

例如文章标题：

```txt
我的 Next.js 学习笔记
```

slug 可以写成：

```txt
nextjs-study-notes
```

前台地址：

```txt
/blog/nextjs-study-notes
```

注意：

```txt
1. slug 不建议写中文
2. slug 不要重复
3. slug 使用小写字母、数字和短横线
```

```txt
status = published
```

```txt
Read：允许
```

## 14.3 为什么要限制 Public 权限

不能让前台读到草稿文章。

错误情况：

```txt
你在后台写了一篇草稿
还没有发布
但前台 API 已经能读到
```

正确情况：

```txt
只有 status = published 的文章才能被前台读取
```

# 20. 封装 Directus API

## 20.1 创建 lib/directus.ts

```ts
import type { Post, Project, Friend, SiteSettings } from "@/types/directus";

const DIRECTUS_URL = process.env.NEXT_PUBLIC_DIRECTUS_URL;

if (!DIRECTUS_URL) {
  throw new Error("NEXT_PUBLIC_DIRECTUS_URL is not defined");
}

async function directusFetch<T>(path: string): Promise<T> {
  const res = await fetch(`${DIRECTUS_URL}${path}`, {
    next: {
      revalidate: 60,
    },
  });

  if (!res.ok) {
    throw new Error(`Directus API 请求失败: ${path}`);
  }

  const json = await res.json();
  return json.data;
}

export function getAssetUrl(fileId?: string) {
  if (!fileId) return "";
  return `${DIRECTUS_URL}/assets/${fileId}`;
}

export async function getPosts(): Promise<Post[]> {
  return directusFetch<Post[]>(
    "/items/posts" +
      "?filter[status][_eq]=published" +
      "&sort=-published_at" +
      "&fields=*,category.*,tags.tags_id.*"
  );
}

export async function getFeaturedPosts(): Promise<Post[]> {
  return directusFetch<Post[]>(
    "/items/posts" +
      "?filter[status][_eq]=published" +
      "&filter[is_featured][_eq]=true" +
      "&sort=-published_at" +
      "&limit=6" +
      "&fields=*,category.*,tags.tags_id.*"
  );
}

export async function getPostBySlug(slug: string): Promise<Post | null> {
  const posts = await directusFetch<Post[]>(
    `/items/posts` +
      `?filter[status][_eq]=published` +
      `&filter[slug][_eq]=${slug}` +
      `&limit=1` +
      `&fields=*,category.*,tags.tags_id.*`
  );

  return posts[0] ?? null;
}

export async function getProjects(): Promise<Project[]> {
  return directusFetch<Project[]>(
    "/items/projects" +
      "?filter[status][_eq]=published" +
      "&sort=sort,-start_date"
  );
}

export async function getFriends(): Promise<Friend[]> {
  return directusFetch<Friend[]>(
    "/items/friends" +
      "?filter[status][_eq]=published" +
      "&sort=sort"
  );
}

export async function getSiteSettings(): Promise<SiteSettings | null> {
  const settings = await directusFetch<SiteSettings[]>(
    "/items/site_settings?limit=1"
  );

  return settings[0] ?? null;
}
```

# 21. 注意 tags 数据结构

Directus 多对多返回的数据可能是这种形式：

```json
{
  "tags": [
    {
      "tags_id": {
        "id": "1",
        "name": "Next.js",
        "slug": "nextjs"
      }
    }
  ]
}
```

所以前台渲染 tags 时可能需要转换。

创建 `lib/utils.ts`：

```ts
import type { Tag } from "@/types/directus";

export function normalizeTags(rawTags: any): Tag[] {
  if (!rawTags || !Array.isArray(rawTags)) {
    return [];
  }

  return rawTags
    .map((item) => item.tags_id ?? item)
    .filter(Boolean);
}

export function formatDate(date?: string) {
  if (!date) return "";

  return new Intl.DateTimeFormat("zh-CN", {
    year: "numeric",
    month: "2-digit",
    day: "2-digit",
  }).format(new Date(date));
}
```

# 35. 常见问题排查

## 35.1 前台请求不到文章

检查：

```txt
1. Directus 是否启动
2. NEXT_PUBLIC_DIRECTUS_URL 是否正确
3. posts 表是否有文章
4. 文章 status 是否为 published
5. Public 权限是否允许读取 posts
6. API 地址是否拼错
```

---

## 35.2 浏览器报 CORS 错误

检查 `docker-compose.yml`：

```yaml
CORS_ENABLED: "true"
CORS_ORIGIN: "http://localhost:3000"
```

如果部署后，改成真实前台域名：

```yaml
CORS_ORIGIN: "https://your-blog.com"
```

---

## 35.3 图片不显示

检查：

```txt
1. cover_image 字段是否有值
2. 是否使用了 /assets/{fileId}
3. Directus 文件权限是否允许 Public 读取
4. 图片 URL 是否正确
```

图片地址通常是：

```txt
http://localhost:8055/assets/文件ID
```

---

## 35.4 tags 不显示

Directus 多对多字段返回结构可能比较特殊。

检查返回数据：

```ts
console.log(post.tags);
```

如果结构是：

```json
[
  {
    "tags_id": {
      "name": "Next.js"
    }
  }
]
```

就需要用 `normalizeTags` 转换。

## 36.4 Nginx 反向代理示例

```nginx
server {
```
