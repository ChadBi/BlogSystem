# 前后端联调修复方案

## 一、概述（Summary）

通过实际探测确认了联调失败的**双重根因**：

1. **后端是空库**：Directus 容器健康运行（`/server/ping` 返回 200，admin 登录成功），但 `posts` 集合根本不存在（API 返回 `You don't have permission to access collection "posts" or it does not exist`）。数据库从未创建过任何集合。
2. **前端带无效 token**：`blog-frontend/.env` 配置 `DIRECTUS_STATIC_TOKEN=123456`，但后端从未生成过这个 static token。Directus 对带 Authorization 头的请求会强制校验，无效即 401，即使 public 角色有权限也不会 fallback。

加之 `lib/directus.ts` 的 `fetchDirectus` 把所有失败（401/403/404/网络异常）**全部静默吞成 null**并回退 mock 数据，导致"页面能打开但全是 mock 数据，控制台一堆错误日志"的假象。

本方案分三步：**①重置后端 schema 与种子数据 → ②前端配置与代码修复 → ③联调验证**。用户已确认选择"清空 Token 走 public 角色"+"重置数据库从零搭建 schema"。

## 三、总体方案

### 3.1 执行顺序

```
Step 1: 重置后端数据库（停容器→删 data.db→启容器→空库）
   ↓
Step 2: 用 admin token 调用 Directus API 自动创建集合、字段、权限、种子数据
   ↓
Step 3: 修复前端 .env（清空 TOKEN、补 ADMIN_PASSWORD/AUTH_SECRET）
   ↓
Step 4: 修复前端代码（getFriends normalize、fetchDirectus 错误日志）
   ↓
Step 5: 启动前端 dev server，逐页验证
```

### 3.2 鉴权策略

- **公开内容**（posts/categories/tags/friends 的读取）：走 public 角色，**不带 token**。前端 `.env` 的 `DIRECTUS_STATIC_TOKEN` 留空。
- **schema 创建与种子数据写入**：用 admin 账号登录获取临时 access_token（有效期 15 分钟），调用 API 完成一次性初始化。**不在前端代码中硬编码 admin token**。
- **前端 admin 后台登录**：与 Directus 完全独立，用前端自己的 `ADMIN_PASSWORD`/`AUTH_SECRET` 环境变量（上次任务已实现）。

## 四、具体改动清单

### 4.1 后端：重置数据库

**操作步骤**（在 `d:\Project\BlogSystem\directus-cms\` 目录执行）：

```powershell
docker compose down
Remove-Item -Path .\database\data.db -Force
docker compose up -d
```

**预期结果**：Directus 启动时创建全新的空 SQLite 数据库，admin 账号根据 `.env` 的 `ADMIN_EMAIL`/`ADMIN_PASSWORD` 重新初始化。

### 4.2 后端：创建 schema 与种子数据（脚本化）

**新建文件**：`directus-cms/seed.mjs`（Node ESM 脚本，不依赖任何 npm 包，仅用内置 fetch）

**脚本职责**：
1. 用 `ADMIN_EMAIL`/`ADMIN_PASSWORD` 调 `POST /auth/login` 获取 access_token
2. 调 `POST /collections` 创建 4 个集合：`posts`、`categories`、`tags`、`friends`
3. 调 `POST /fields` 为每个集合添加字段（按 [docs/directus-schema.md](file:///d:\Project\BlogSystem\blog-frontend\docs\directus-schema.md) 定义）
4. 调 `POST /relations` 创建 M2O（posts→categories）和 M2M（posts↔tags）
5. 调 `POST /permissions` 为 public 角色授予 4 个集合的读权限（posts 限制 `status=published`）
6. 调 `POST /items/categories`、`POST /items/tags`、`POST /items/posts` 插入 3 个分类、5 个标签、3 篇示例文章
7. 输出每一步的结果，失败即退出

**字段定义**（基于 [docs/directus-schema.md](file:///d:\Project\BlogSystem\blog-frontend\docs\directus-schema.md) 与 [types/post.ts](file:///d:\Project\BlogSystem\blog-frontend\types\post.ts)）：

- **categories**: name(string), slug(string), description(text), icon(string)
- **tags**: name(string), slug(string), color(string)
- **posts**: title(string), slug(string), summary(text), content(text), cover(file), status(string,draft|published), published_at(timestamp), category(M2O→categories), tags(M2M→tags), views(int), likes(int), comments(int)
- **friends**: name(string), role(string), description(text), url(string), avatar(file), tags(json)

**public 角色权限**：
- `categories`：read 全部
- `tags`：read 全部
- `posts`：read，且 `status` 字段 preset=`published`（即只允许读已发布）
- `friends`：read 全部

**运行方式**：
```powershell
node directus-cms/seed.mjs
```

脚本读取 `directus-cms/.env`（用 Node 内置 `fs` 简单解析，不引入 dotenv）。可重复执行（先尝试删除已存在的集合再创建，或用幂等的 upsert 逻辑）。

### 4.4 前端：修复 getFriends 的 avatar normalize

**修改文件**：[lib/directus.ts](file:///d:\Project\BlogSystem\blog-frontend\lib\directus.ts) 第 114-117 行

**现状**：
```ts
export async function getFriends(): Promise<Friend[]> {
  const data = await fetchDirectus<{ data: Friend[] }>('/items/friends?sort=name');
  return data?.data ?? friends;
}
```

**改为**：
```ts
export async function getFriends(): Promise<Friend[]> {
  const data = await fetchDirectus<{ data: DirectusItem[] }>('/items/friends?sort=name');
  if (!data) return friends;
  return data.data.map((item) => ({
    id: String(item.id),
    name: item.name,
    role: item.role ?? '',
    description: item.description ?? '',
    url: item.url ?? '#',
    avatar: item.avatar ? `${DIRECTUS_URL}/assets/${item.avatar}` : '🦈',
    tags: Array.isArray(item.tags) ? item.tags : []
  }));
}
```

**理由**：Directus 中 `friends.avatar` 是 file UUID（字符串），需拼成 `${DIRECTUS_URL}/assets/{uuid}` 才能在 `<img src>` 中使用。mock 数据的 avatar 是 emoji，保留为 fallback。

### 4.5 前端：增强 fetchDirectus 的错误日志

**修改文件**：[lib/directus.ts](file:///d:\Project\BlogSystem\blog-frontend\lib\directus.ts) 第 11-31 行

**现状**：所有失败都只打一行 `console.error`，无法区分错误类型。

**改为**：在 401/403 时额外提示"检查 DIRECTUS_STATIC_TOKEN 配置"，在 404 时提示"集合不存在，请运行 seed 脚本"。

```ts
async function fetchDirectus<T>(path: string): Promise<T | null> {
  if (!DIRECTUS_URL) {
    console.error('[directus] DIRECTUS_URL 未配置，回退到 mock 数据');
    return null;
  }

  try {
    const res = await fetch(`${DIRECTUS_URL}${path}`, {
      headers: TOKEN ? { Authorization: `Bearer ${TOKEN}` } : {},
      next: { revalidate: 60 }
    });
    if (!res.ok) {
      const hint = res.status === 401 || res.status === 403
        ? '（鉴权失败：若 DIRECTUS_STATIC_TOKEN 已配置但无效，请清空它走 public 角色）'
        : res.status === 404
          ? '（集合不存在：请运行 node directus-cms/seed.mjs 初始化 schema）'
          : '';
      console.error(`[directus] 请求失败: ${res.status} ${res.statusText} - ${path} ${hint}`);
      return null;
    }
    return await res.json();
  } catch (err) {
    console.error(`[directus] 网络异常: ${path}`, err instanceof Error ? err.message : err);
    return null;
  }
}
```

**理由**：不改变"失败回退 mock"的核心行为（避免页面 500），但让错误日志可直接定位根因，避免下次联调时再次踩坑。

### 4.6 前端：修复 Category.count 聚合

**修改文件**：[lib/directus.ts](file:///d:\Project\BlogSystem\blog-frontend\lib\directus.ts) `getCategories` 函数

**现状**：直接返回 Directus 原始数据，count 字段不存在，分类页显示"0 篇"。

**改为**：仿照 `getTags` 的模式，从 `getPosts` 结果聚合 count：

```ts
export async function getCategories(): Promise<Category[]> {
  const data = await fetchDirectus<{ data: DirectusItem[] }>('/items/categories?sort=name');
  const raw: Category[] = data
    ? data.data.map((item) => ({
        id: String(item.id),
        name: item.name,
        slug: item.slug,
        description: item.description ?? '',
        icon: item.icon ?? '🧱'
      }))
    : categories;
  const allPosts = await getPosts();
  const countMap = new Map<string, number>();
  for (const post of allPosts) {
    const key = post.category?.id ?? post.category?.slug;
    if (key) countMap.set(key, (countMap.get(key) ?? 0) + 1);
  }
  return raw.map((c) => ({ ...c, count: countMap.get(c.id ?? c.slug) ?? 0 }));
}
```

## 五、假设与决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| Token 策略 | 清空 `DIRECTUS_STATIC_TOKEN`，走 public 角色 | 用户选择；博客公开内容本就应匿名可读，最简单可靠 |
| Schema 创建方式 | Node 脚本调 Directus API | 用户选择"从零搭建"；脚本化可重复执行、可纳入版本控制，优于手动 UI 操作 |
| 数据库重置 | 删 data.db 重建 | 用户选择；当前库本就是空的（无集合），无数据可丢 |
| 种子数据量 | 3 分类 + 5 标签 + 3 文章 | 够覆盖所有页面（首页/列表/详情/分类/归档/搜索）的渲染验证 |
| mock 回退机制 | 保留 | 避免后端故障时页面 500；但增强日志让失败可见 |
| `getFriends` avatar | 拼 `${DIRECTUS_URL}/assets/{uuid}` | Directus file 字段返回 UUID，需拼完整 URL |
| `Category.count` | 从 posts 聚合 | 仿 `getTags` 既有模式，无需 Directus aggregate 查询 |
| admin 后台密码 | 前端 `.env` 独立配置 `ADMIN_PASSWORD` | 与 Directus admin 密码解耦，更安全 |
| seed 脚本依赖 | 零依赖，仅用 Node 内置 fetch + fs | Node 18+ 内置 fetch，无需 npm install |
