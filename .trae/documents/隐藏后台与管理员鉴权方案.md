# 隐藏后台与管理员鉴权方案

## 一、概述（Summary）

将 `/dashboard` 与 `/editor` 两个公开暴露且无鉴权的原型页面**合并为单一 `/admin` 路径**，从公开导航 `Sidebar` 中移除入口，并引入**轻量级密码鉴权**（环境变量密码 + HttpOnly Cookie + Next.js Middleware），使后台仅能由管理员通过手动输入 `/admin` 并登录后访问。不引入第三方认证库，全部使用 Node.js / Edge Runtime 内置的 Web Crypto API。

## 三、总体架构

### 3.1 鉴权流程

```
访客输入 /admin
      │
      ▼
middleware.ts 拦截 /admin
      │
      ├─ cookie admin_session 有效 → 放行，渲染 /admin 页面
      │
      └─ cookie 缺失/无效 → 302 重定向到 /login
                                    │
                                    ▼
                              /login 页面（公开）
                              用户输入密码 → POST /api/login
                                    │
                                    ├─ 密码正确 → 设置 HttpOnly cookie → 跳转 /admin
                                    └─ 密码错误 → 显示错误提示
```

### 3.2 /admin 页面合并策略

`/admin` 是单一 Server Component 入口，通过 URL search param `?view=editor` 切换子视图：

- `/admin`（默认）→ 仪表盘视图（服务端获取 `getPosts()` 数据）
- `/admin?view=editor` → 写作编辑器视图（静态 UI）

顶部 Tab 导航为 Client Component，点击通过 `router.push` 改变 query，Server Component 据此重新渲染对应视图。此为 App Router 标准模式，无需重构为 SPA。

### 3.3 密码验证算法

采用 HMAC-SHA256，`lib/auth.ts` 中用 **Web Crypto API** 实现（同时在 Edge Runtime 的 middleware 与 Node.js Runtime 的 Route Handler 中可用）：

- 登录时：`token = HMAC_SHA256(AUTH_SECRET, ADMIN_PASSWORD)` → 写入 cookie
- 验证时：重算 `HMAC_SHA256(AUTH_SECRET, ADMIN_PASSWORD)` → 与 cookie 值恒定时间比较

## 四、具体改动清单

### 4.1 新建文件

#### ① `blog-frontend/lib/auth.ts` — 共享鉴权工具

**职责**：提供 HMAC 令牌生成 / 验证、cookie 配置常量。被 `middleware.ts` 与 `app/api/login/route.ts` 共用，保证算法一致。

**关键内容**：
- `SESSION_COOKIE = 'admin_session'`
- `SESSION_MAX_AGE = 60 * 60 * 24 * 7`（7 天）
- `generateSessionToken(): Promise<string>` — 读取 `process.env.AUTH_SECRET` 与 `process.env.ADMIN_PASSWORD`，用 `crypto.subtle` 计算 HMAC hex
- `verifySessionToken(token: string): Promise<boolean>` — 重算期望值并恒定时间比较
- `hex(bytes: Uint8Array): string` — 辅助函数（Edge Runtime 无 `Buffer`）

#### ② `blog-frontend/middleware.ts` — 路由保护

**职责**：拦截 `/admin` 及其子路径，校验 cookie，未登录重定向 `/login`。

**关键内容**：
```ts
export async function middleware(request: NextRequest) {
  const token = request.cookies.get(SESSION_COOKIE)?.value;
  const ok = token ? await verifySessionToken(token) : false;
  if (!ok) {
    return NextResponse.redirect(new URL('/login', request.url));
  }
  return NextResponse.next();
}

export const config = {
  matcher: ['/admin/:path*'],
};
```

**说明**：matcher 仅匹配 `/admin`，不影响 `/login`、`/api/login`、公开页面与静态资源。

#### ③ `blog-frontend/app/api/login/route.ts` — 登录接口

**职责**：POST 接收 `{ password }`，校验后设置 HttpOnly cookie。

**逻辑**：
1. 解析 JSON body，取 `password`
2. 与 `process.env.ADMIN_PASSWORD` 比较；不一致返回 `401 { error: '密码错误' }`
3. 一致则 `const token = await generateSessionToken()`
4. `response.cookies.set(SESSION_COOKIE, token, { httpOnly: true, secure: process.env.NODE_ENV === 'production', sameSite: 'lax', path: '/', maxAge: SESSION_MAX_AGE })`
5. 返回 `{ ok: true }`

#### ④ `blog-frontend/app/api/logout/route.ts` — 登出接口

**职责**：POST 清除 cookie，返回 `{ ok: true }`。

**逻辑**：`response.cookies.set(SESSION_COOKIE, '', { maxAge: 0, path: '/' })`

#### ⑤ `blog-frontend/app/login/page.tsx` — 登录页

**职责**：公开页面，密码输入表单。

**实现**：
- `'use client'` Client Component
- 复用 `PageShell`（`showSidebar={true}`，与公开页面视觉一致）与 `PixelCard` 组件保持像素风格
- 表单：密码 input（type=password）+ 提交按钮
- 提交时 `fetch('/api/login', { method: 'POST', body: JSON.stringify({ password }) })`
- 成功 → `router.push('/admin')`；失败 → 显示错误文案
- 提交期间禁用按钮，防止重复提交
- `metadata`：`{ title: '登录 - Shark Tech Blog' }`

#### ⑥ `blog-frontend/app/admin/page.tsx` — 合并后的后台入口

**职责**：单一 `/admin` 路径，根据 `searchParams.view` 渲染仪表盘或编辑器。

**实现**：
- `export const dynamic = 'force-dynamic'`（因依赖 cookie 鉴权，禁用静态生成）
- Server Component，签名：`({ searchParams }: { searchParams: { view?: string } })`
- `const view = searchParams.view`
- 逻辑分支：
  - `view === 'editor'` → 渲染 `<AdminShell view="editor">` 包裹编辑器内容（从旧 `editor/page.tsx` 迁移）
  - 否则 → `const posts = await getPosts()`，渲染 `<AdminShell view="dashboard">` 包裹仪表盘内容（从旧 `dashboard/page.tsx` 迁移）
- `metadata`：`{ title: '管理后台 - Shark Tech Blog', robots: { index: false, follow: false } }`（禁止搜索引擎索引）
- `PageShell showSidebar={false}`（后台不显示公开 Sidebar）

#### ⑦ `blog-frontend/components/AdminShell.tsx` — 后台布局壳

**职责**：包裹 /admin 内容，提供 Tab 切换与退出登录按钮。

**实现**：
- 顶部栏：左侧标题"管理后台"，右侧"退出登录"按钮（Client Component 子组件，点击 fetch `/api/logout` 后 `router.push('/')`）
- Tab 导航：`仪表盘`（链接 `/admin`）/ `写作`（链接 `/admin?view=editor`），高亮当前 view
- Tab 部分为 Client Component（用 `usePathname` + `useSearchParams` 判断当前 view，`useRouter` 切换）
- 主体区域渲染 `children`

> 说明：因 `AdminShell` 需要客户端交互（退出、Tab 切换），将其设为 Client Component，接收 `view` prop 与 `children`。Server Component `/admin/page.tsx` 负责数据获取，把渲染好的内容作为 children 传入。

## 五、假设与决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 认证库 | 不引入第三方库，用 Web Crypto API | 用户选择"简单密码保护"，单人管理员博客无需 NextAuth；Web Crypto 在 Edge/Node 双 runtime 可用 |
| Cookie 内容 | HMAC-SHA256 签名值 | 比直接存密码哈希更安全；比 JWT 简单；防篡改 |
| Cookie 有效期 | 7 天 | 单人博客常用周期，平衡便利与安全 |
| Cookie Secure 标志 | 仅生产环境开启 | 开发环境为 http，强开 Secure 会导致 cookie 无法写入 |
| 视图切换方式 | URL search param `?view=editor` | App Router 标准模式，可分享/书签，服务端按需获取数据 |
| 旧路径处理 | 直接删除，不保留重定向 | 用户选"合并为单一路径"，原型无外部依赖，保持简洁 |
| 登录失败限流 | 不实现 | 单人博客场景，暴力破解风险低；后续可由 nginx 或中间件层补充 |
| 搜索引擎索引 | /admin 与 /login 设 `robots: noindex` | 防止后台/登录页被搜索引擎收录 |
| `dynamic = 'force-dynamic'` | /admin 页面启用 | 依赖鉴权 cookie，不能静态生成 |
